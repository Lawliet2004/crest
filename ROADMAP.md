# Crest Browser roadmap

| Phase | Status | Next validation or implementation |
| --- | --- | --- |
| 0 · Feasibility | CEF prototype builds and runs on Linux. | Qualify a Chromium fork build runner and establish engine patch and redistribution procedures. |
| 1 · Desktop browsing | First build with navigation, tabs, bookmarks, history, downloads, saved settings, DevTools, a default-deny permission policy, and an Ubuntu developer package. | Qualify native Wayland and more Linux distributions, deepen browser regression coverage, and add per-site permission controls. |
| 2 · Experience | Branded new-tab page and native controls are in place. | Add dashboard widgets, personal workspaces, and keyboard and accessibility polish. |
| 3 · Compatibility | Planned. | Test Google web apps, OAuth, codecs, and Chrome Web Store and extension flows on the production engine candidate. |
| 4 · Agent Spaces | Planned. | Add independent profiles, explicit grants, and background activity reporting. |
| 5 · Agent integration | Planned. | Add the scoped Rust MCP server and CDP or BiDi adapter after verifying two-space isolation. |
| 6 · Customization | Planned. | Add a widget SDK, install approval, and rollback. |
| 7 · Hardening | Planned. | Measure memory, startup, and responsiveness against Chromium and Firefox. Validate releases and sandbox behavior across supported Linux distributions. |
