# Crest Browser architecture

## ADR 001 — Engine boundary for the Linux milestone

**Decision.** Build the first desktop milestone in Rust using pinned CEF binaries and the `cef-rs` bindings. CEF supplies Chromium's Blink, V8, network stack, process model, and native Views toolkit. Keep browser state and policy in Rust so they can move to a Chromium integration behind a different engine adapter. A maintained Chromium fork remains the production candidate, pending separate build, distribution, compatibility, and security-update validation.

| Criterion | A. Chromium fork | B. Rust desktop application with CEF | C. Servo |
| --- | --- | --- | --- |
| Google websites and sign-in | Chromium baseline. Site and OAuth behavior require live tests. | Chromium rendering baseline. Embedded-user-agent policy and login flows require validation. | Web-platform gaps and login flows require validation. |
| Chrome extensions and DevTools | Native Chrome extension framework and DevTools. Web Store integration and identity need separate validation. | DevTools available. Chrome-style and Alloy-style views expose different extension surfaces. | No Chromium extension framework. Engine-specific developer tools. |
| Profiles and agent automation | Native profiles and CDP. A policy broker is Crest work. | CEF request contexts and DevTools APIs. Isolation and an agent-facing API are Crest work. | Profile and automation support would need separate evaluation and engineering. |
| Linux packaging and Rust | GN/Ninja Chromium build with Rust static libraries and CXX or Mojo integration. | Cargo workspace with a version-matched CEF runtime and Rust bindings. | Embeddable Rust engine with a separate Linux distribution and compatibility effort. |
| Resource use and upkeep | Requires build runners, patch rebases, release infrastructure, and measurements. | Small integration surface. Each engine bump still requires verification and a new runtime bundle. | Requires engine-specific testing and ongoing upstream tracking. |

The development host is x86-64 Ubuntu 26.04.1 LTS with 12 logical CPUs, 14 GiB of reported RAM, 32 GiB of swap, and 234 GiB free on the project filesystem at inspection. About 2.7 GiB of RAM was available. The host supports unprivileged user namespaces. Chromium's build guide recommends more than 16 GB of RAM and at least 100 GB free. For a fork, use a dedicated build runner and verify signed, reproducible release inputs and an upstream security-update process. ## Implementation boundary

`crest-core` owns URL resolution, the profile schema, and atomic storage. `crest-browser` owns native controls and tab lifecycle. Its CEF adapter implements navigation, display, permission, and download callbacks. Keeping browser views attached during tab and layout changes preserves live page state. Restored background tabs create a renderer when first selected.

Rust application code uses `url` for URL parsing and IDNA, `serde` and `serde_json` for structured state, `tempfile` for atomic file replacement, `dirs` for Linux directory conventions, and `tiny-skia` to draw native toolbar icons at standard and high DPI. The non-Rust runtime is prebuilt CEF and its Chromium libraries, which provide rendering, JavaScript, networking, the Linux sandbox, and the native Views toolkit. About 94% of the physical lines in the two crate source directories are Rust. The remaining text source is the new-tab HTML and CSS. This count includes inline Rust tests and excludes binary artwork, build and test harnesses, and the engine. Measuring the combined application and engine Rust share requires an inventory of the matching Chromium and CEF sources. A project source license is still to be selected. [CEF Views](https://cef-builds.spotifycdn.com/docs/156.0/classCefWindow.html)

For the later agent phases, evaluate the official Rust MCP SDK as the transport and schema layer. Compare CDP and WebDriver BiDi for the automation adapter, and use the DevTools and Playwright MCP projects as interoperability references. The automation boundary still needs a capability model that independently checks every operation against the client and Agent Space.
